# M0 — Schema, RLS and Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the complete Postgres schema, RLS policies, gift state machine, and slot-reservation logic for the birthday gifting app, with pgTAP tests proving that a sender can never read a recipient's address.

**Architecture:** A local Supabase project. Every table lives in `public` with RLS enabled; every privileged helper lives in a non-exposed `private` schema as a `security definer` function. Clients get read access shaped by RLS and write access only where a row is unambiguously theirs — all gift and people writes go through server-side functions. There is no UI in this milestone; the deliverable is a migration set plus a green `supabase test db` run.

**Tech Stack:** Postgres 15 (Supabase), Supabase CLI 2.78.1, pgTAP, pgcrypto, dblink (tests only).

**Spec:** `docs/superpowers/specs/2026-08-22-birthday-gifting-app-design.md`

## Global Constraints

- All identifiers lowercase with underscores. Never quoted CamelCase.
- Primary keys are `bigint generated always as identity`, except `profiles.id` which is `uuid` referencing `auth.users(id)`.
- Timestamps are `timestamptz`, never `timestamp`. Dates that mean a calendar day (`birthday`, `occasion_date`, `slot_date`) are `date`.
- Strings are `text`, never `varchar(n)`. Constrain with `check` when a format matters.
- Money is `bigint` minor units (paise) plus a `currency text` column. Never `float`, never `numeric` for payment amounts.
- Every foreign key column gets an index. Postgres does not create them.
- Every table in `public` has `enable row level security`. A table with RLS enabled and no policy denies everything to `anon` and `authenticated` — that is the intended state for tables written only by Edge Functions.
- Every `auth.uid()` call inside a policy is wrapped as `(select auth.uid())` so it is evaluated once, not per row.
- `security definer` functions always set `search_path = ''`, always fully qualify table names, and always have `execute` revoked from `public`, `anon`, and `authenticated` unless a client is explicitly meant to call them.
- Constraints added in a later migration use a `do $$ ... $$` existence check. Postgres has no `add constraint if not exists`.
- No client writes to `gifts`. Ever. (Spec §5 rule 1.)
- Migrations are append-only. Never edit a committed migration; add a new one.

## Deviations from the spec, decided while planning

Three points where the spec as written could not be built. The spec is the
authority on intent; these are the corrections.

1. **`addresses` is owned by a `person`, not a `profile`.** Spec §4.2 says
   addresses are owned by a profile, but a non-user recipient confirming through
   the tokenized web page (spec §6 rule 5) has no profile. The owner column is
   `owner_person_id`, which covers users and non-users with one rule.
2. **The slot hold is not taken inside the payment transaction.** Spec §5 rule 3
   says the reservation happens "inside the payment transaction", but the
   payment provider call is an HTTP round trip and holding a row lock across it
   would serialize checkout and risk long lock waits. Instead: a short
   transaction reserves the slot and creates the gift as `draft` with
   `slot_hold_expires_at`; the payment call happens outside any transaction; a
   sweep releases expired holds. This preserves the actual requirement — a
   Saturday can never be oversold — without holding locks across the network.
3. **`gifts` gets a denormalized `delivery_city`.** RLS is row-level, so it
   cannot hide one column from the sender while showing it to the recipient.
   The sender's city visibility (spec §6 rule 2) is implemented by writing the
   city onto the gift at confirmation time; the sender never gains access to the
   `addresses` row itself.

```sql
create schema if not exists private;

-- Nothing outside the database may touch this schema.
revoke all on schema private from public;
revoke all on schema private from anon, authenticated;

create table private.config (
  key text primary key,
  value text not null
);

alter table private.config enable row level security;
-- No policies: anon and authenticated get nothing. service_role bypasses RLS,
-- which is why the pepper must never be handed to a browser client.

-- Local/dev pepper. Production sets its own value out of band; rotating it
-- invalidates every stored people.phone_e164_hash, so it is set once at launch.
insert into private.config (key, value)
values ('phone_pepper', 'dev-pepper-replace-in-production')
on conflict (key) do nothing;

create or replace function private.phone_hash(p_phone text)
returns text
language sql
security definer
set search_path = ''
stable
as $$
  select encode(
    extensions.hmac(
      p_phone,
      (select value from private.config where key = 'phone_pepper'),
      'sha256'
    ),
    'hex'
  );
$$;

revoke execute on function private.phone_hash(text) from public;
revoke execute on function private.phone_hash(text) from anon, authenticated;

-- is_staff is referenced by ops policies in Task 11. It reads profiles, which
-- Task 3 creates, so the body is deliberately tolerant of that table not
-- existing yet during this migration's own transaction.
create or replace function private.is_staff()
returns boolean
language plpgsql
security definer
set search_path = ''
stable
as $$
declare
  v_is_staff boolean;
begin
  select p.is_staff into v_is_staff
  from public.profiles p
  where p.id = (select auth.uid());
  return coalesce(v_is_staff, false);
exception
  when undefined_table then
    return false;
end;
$$;

revoke execute on function private.is_staff() from public;
revoke execute on function private.is_staff() from anon;
```

Note: `authenticated` keeps `execute` on `is_staff()` because policies evaluate
it as the calling role.

```sql
create table public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  handle text not null unique,
  display_name text not null,
  date_of_birth date,
  city text,
  avatar_url text,
  is_staff boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  -- 40 chars, not 20: the signup trigger below generates a handle from the
  -- user's uuid, which is 33 characters until onboarding sets a real one.
  constraint profiles_handle_format check (handle ~ '^[a-z0-9_]{3,40}$'),
  constraint profiles_dob_sane check (
    date_of_birth is null
    or (date_of_birth > date '1900-01-01' and date_of_birth <= current_date)
  )
);

alter table public.profiles enable row level security;

-- A profile is readable and writable only by the person it belongs to.
-- Other users never read this table: public identity lives on public.people,
-- which Task 4 creates. That keeps a user's city and date of birth private by
-- default rather than by remembering to filter columns.
create policy profiles_select_own
  on public.profiles
  for select
  to authenticated
  using (id = (select auth.uid()));

create policy profiles_update_own
  on public.profiles
  for update
  to authenticated
  using (id = (select auth.uid()))
  with check (id = (select auth.uid()));

-- No insert policy: profiles are created by the trigger below, not by clients.
-- No delete policy: account deletion cascades from auth.users.

-- is_staff is set by a database administrator only. Revoking the column from
-- the update grant stops a user flipping their own flag through the API.
revoke update (is_staff) on public.profiles from authenticated;

create or replace function private.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  insert into public.profiles (id, handle, display_name)
  values (
    new.id,
    'u' || replace(new.id::text, '-', '')::text,
    coalesce(new.raw_user_meta_data ->> 'display_name', 'New user')
  );
  return new;
end;
$$;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function private.handle_new_user();
```

```sql
-- Phone numbers that must never be imported again (spec §6 rule 6).
create table private.suppressions (
  phone_e164_hash text primary key,
  created_at timestamptz not null default now()
);

alter table private.suppressions enable row level security;
-- No policies, and the schema is not API-exposed: server-side access only.

create table public.people (
  id bigint generated always as identity primary key,
  phone_e164_hash text not null unique,
  profile_id uuid unique references public.profiles (id) on delete set null,
  display_name text not null,
  birthday date,
  created_at timestamptz not null default now(),
  constraint people_phone_hash_format check (phone_e164_hash ~ '^[0-9a-f]{64}$'),
  constraint people_birthday_sane check (
    birthday is null
    or (birthday > date '1900-01-01' and birthday <= current_date)
  )
);

create index people_profile_id_idx on public.people (profile_id);

alter table public.people enable row level security;

create table public.celebrations (
  id bigint generated always as identity primary key,
  celebrator_profile_id uuid not null references public.profiles (id) on delete cascade,
  person_id bigint not null references public.people (id) on delete cascade,
  nickname text,
  source text not null,
  created_at timestamptz not null default now(),
  constraint celebrations_source_valid check (source in ('contacts', 'search', 'manual')),
  constraint celebrations_unique_edge unique (celebrator_profile_id, person_id)
);

-- The unique constraint indexes (celebrator, person); person_id needs its own
-- index for the reverse lookup ("who celebrates me") and for cascades.
create index celebrations_person_id_idx on public.celebrations (person_id);

alter table public.celebrations enable row level security;

create table public.blocks (
  id bigint generated always as identity primary key,
  blocker_profile_id uuid not null references public.profiles (id) on delete cascade,
  blocked_profile_id uuid not null references public.profiles (id) on delete cascade,
  created_at timestamptz not null default now(),
  constraint blocks_unique_pair unique (blocker_profile_id, blocked_profile_id),

-- Resolve a phone number to a person, creating the row if needed. Returns
-- null when the number is suppressed, which callers must treat as "skip this
-- contact", not as an error.
create or replace function private.upsert_person(
  p_phone text,
  p_display_name text,
  p_birthday date default null
)
returns bigint
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_hash text := private.phone_hash(p_phone);
  v_id bigint;
begin
  if exists (select 1 from private.suppressions s where s.phone_e164_hash = v_hash) then
    return null;
  end if;

  select p.id into v_id from public.people p where p.phone_e164_hash = v_hash;

  if v_id is not null then
    -- Never overwrite a name or birthday the person set themselves; only fill
    -- blanks left by earlier imports.
    update public.people
    set birthday = coalesce(birthday, p_birthday)
    where id = v_id and profile_id is null;
    return v_id;
  end if;

  insert into public.people (phone_e164_hash, display_name, birthday)
  values (v_hash, p_display_name, p_birthday)
  returning id into v_id;

  return v_id;
end;
$$;

-- Link a signed-up profile to its person row, creating the row if this number
-- was never imported by anyone.

  p_profile_id uuid,
  p_phone text
)
returns bigint
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_hash text := private.phone_hash(p_phone);
  v_id bigint;
  v_name text;
  v_dob date;
begin
  select p.display_name, p.date_of_birth into v_name, v_dob
  from public.profiles p where p.id = p_profile_id;

  insert into public.people (phone_e164_hash, display_name, birthday, profile_id)
  values (v_hash, coalesce(v_name, 'New user'), v_dob, p_profile_id)
  on conflict (phone_e164_hash) do update

        display_name = coalesce(v_name, public.people.display_name),

  returning id into v_id;

  return v_id;
end;
$$;

-- The "not me / remove me" path. Hard-deletes the person and every edge
-- pointing at them, then records the hash so a re-import cannot resurrect it.
create or replace function private.suppress_person(p_person_id bigint)
returns void
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_hash text;
begin
  select p.phone_e164_hash into v_hash from public.people p where p.id = p_person_id;

  if v_hash is null then
    raise exception 'person % not found', p_person_id;
  end if;

  insert into private.suppressions (phone_e164_hash)
  values (v_hash)
  on conflict (phone_e164_hash) do nothing;

  delete from public.people where id = p_person_id;
end;
$$;
```

### Task 7: Prove the slot cap holds under concurrent checkout

Task 6 proved capacity is honoured by one session. This proves two sessions
racing the last slot produce exactly one winner — the failure mode that sells
forty cakes for a Saturday you can make fifteen of.

The test uses `dblink` to open two real connections, holds a transaction open
on one, and asserts the other **blocks** rather than reading a stale count.

**Files:**
- Modify: `supabase/seed.sql` (append the race helper)
- Create: `supabase/tests/database/06_slot_concurrency.test.sql`

**Interfaces:**
- Consumes: `private.reserve_slot(bigint)`, the committed `Race Test Area` slot.
- Produces: `tests.race_last_slot() returns table(blocked boolean, loser_sqlstate text)`

- [ ] **Step 1: Append the race helper to seed.sql**

```sql
-- Opens two real connections and races them for the last unit of capacity on
-- the committed 'Race Test Area' slot. Returns whether the second connection
-- was made to wait, and the SQLSTATE it eventually failed with.
create or replace function tests.race_last_slot()
returns table (blocked boolean, loser_sqlstate text)
language plpgsql
as $$
declare
  v_conn text := 'dbname=postgres user=postgres password=postgres host=127.0.0.1 port=54322';
  v_slot bigint;
  v_blocked boolean;
  v_sqlstate text := null;
begin
  select s.id into v_slot
  from public.delivery_slots s
  join public.service_areas a on a.id = s.service_area_id
  where a.name = 'Race Test Area';

  perform extensions.dblink_connect('race_a', v_conn);
  perform extensions.dblink_connect('race_b', v_conn);

  -- Reset committed state so the test is repeatable without a db reset.
  perform extensions.dblink_exec(
    'race_a', format('update public.delivery_slots set reserved = 0 where id = %s', v_slot));

  -- Connection A takes the only unit and holds its transaction open.
  perform extensions.dblink_exec('race_a', 'begin');
  perform extensions.dblink_exec('race_a', format('select private.reserve_slot(%s)', v_slot));

  -- Connection B tries for the same unit and must wait on A's row lock.
  perform extensions.dblink_send_query('race_b', format('select private.reserve_slot(%s)', v_slot));
  perform pg_sleep(0.3);
  v_blocked := extensions.dblink_is_busy('race_b') = 1;

  -- A commits; B now re-evaluates the predicate and must lose.
  perform extensions.dblink_exec('race_a', 'commit');

  begin
```

```sql
-- deliveries cannot both advance the same gift.
create or replace function private.gift_transition(
  p_gift_id bigint,
  p_to public.gift_status,
  p_actor uuid default null
)
returns public.gifts
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_from public.gift_status;
  v_row public.gifts;
begin
  select g.status into v_from
  from public.gifts g
  where g.id = p_gift_id
  for update;

  if v_from is null then
    raise exception 'gift % not found', p_gift_id using errcode = '23503';
  end if;

  if not exists (
    select 1 from private.gift_transitions t
    where t.from_status = v_from and t.to_status = p_to
  ) then
    raise exception 'illegal gift transition % to %', v_from, p_to
      using errcode = '23514';
  end if;

  -- Unlock the guard trigger for this statement only.
  perform set_config('app.gift_transition', 'on', true);

  update public.gifts
  set status = p_to,
      updated_at = now()
  where id = p_gift_id
  returning * into v_row;

  perform set_config('app.gift_transition', 'off', true);

  insert into public.gift_events (gift_id, from_status, to_status, actor_profile_id)
  values (p_gift_id, v_from, p_to, p_actor);

  return v_row;
end;
$$;

-- Blocks any status write that did not come through gift_transition. RLS
-- cannot do this job, because the service role bypasses RLS and Edge
-- Functions run as the service role.
create or replace function private.guard_gift_status()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  if new.status is distinct from old.status
     and coalesce(current_setting('app.gift_transition', true), 'off') <> 'on' then
    raise exception 'gift status must change through private.gift_transition';
  end if;
  return new;
end;
$$;

create trigger gifts_guard_status
  before update on public.gifts
  for each row execute function private.guard_gift_status();
```

```sql
-- Webhook idempotency. A provider that delivers the same event twice must not
-- advance a gift twice or refund twice.
create table public.payment_events (
  id bigint generated always as identity primary key,
  provider text not null default 'razorpay',
  provider_event_id text not null unique,
  gift_id bigint references public.gifts (id) on delete set null,
  payload jsonb,
  created_at timestamptz not null default now()
);

create index payment_events_gift_id_idx on public.payment_events (gift_id);

alter table public.payment_events enable row level security;
-- No policies: service role only.

-- Reserve the slot and create the gift in one short transaction. The payment
-- provider is called by the Edge Function afterwards, outside any transaction,
-- so no row lock is ever held across a network round trip.
create or replace function private.create_gift(
  p_sender uuid,
  p_recipient_person_id bigint,
  p_product_id bigint,
  p_slot_id bigint,
  p_occasion_date date,
  p_message text default null,
  p_hold_minutes int default 15
)
returns public.gifts
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_row public.gifts;
  v_area bigint;
  v_price bigint;
begin
  if p_sender is null then
    raise exception 'a gift needs a sender';
  end if;

  if p_recipient_person_id = (
    select p.id from public.people p where p.profile_id = p_sender
  ) then
    raise exception 'you cannot send a cake to yourself';
  end if;

  select pr.service_area_id, pr.price_minor into v_area, v_price
  from public.products pr
  where pr.id = p_product_id and pr.is_active;

  if v_area is null then
    raise exception 'product % is not available', p_product_id;
  end if;

  -- The slot must belong to the same service area as the product.
  if not exists (
    select 1 from public.delivery_slots s
    where s.id = p_slot_id and s.service_area_id = v_area
  ) then
    raise exception 'slot % is not in the product''s service area', p_slot_id
      using errcode = '23514';
  end if;

  perform private.reserve_slot(p_slot_id);

  insert into public.gifts (
    sender_profile_id, recipient_person_id, product_id, service_area_id,
    slot_id, occasion_date, amount_minor, message, status, slot_hold_expires_at
  ) values (
    p_sender, p_recipient_person_id, p_product_id, v_area,
    p_slot_id, p_occasion_date, v_price, p_message, 'draft',
    now() + make_interval(mins => p_hold_minutes)
  )
  returning * into v_row;

  insert into public.gift_events (gift_id, from_status, to_status, actor_profile_id)
  values (v_row.id, null, 'draft', p_sender);

  return v_row;
end;
$$;

-- Called by the payment webhook. Idempotent on provider_event_id.
create or replace function private.mark_gift_paid(
  p_gift_id bigint,
  p_payment_ref text,
  p_provider_event_id text
)
returns public.gifts
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_row public.gifts;
begin
  insert into public.payment_events (provider_event_id, gift_id)
  values (p_provider_event_id, p_gift_id)
  on conflict (provider_event_id) do nothing;

  if not found then
    -- Already processed. Return current state rather than replaying.
    select * into v_row from public.gifts where id = p_gift_id;
    return v_row;
  end if;

  perform set_config('app.gift_transition', 'on', true);
  update public.gifts
  set payment_ref = p_payment_ref,
      slot_hold_expires_at = null
  where id = p_gift_id;
  perform set_config('app.gift_transition', 'off', true);

  v_row := private.gift_transition(p_gift_id, 'paid');
  v_row := private.gift_transition(p_gift_id, 'awaiting_confirm');

  return v_row;
end;
$$;

)
returns public.gifts
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_gift public.gifts;
  v_address_id bigint;
  v_area_name text;
begin
  select * into v_gift
  from public.gifts
  where confirm_token = p_confirm_token
  for update;

  if v_gift.id is null then
    raise exception 'unknown confirmation link';
  end if;

  if v_gift.confirm_token_used_at is not null then
    raise exception 'this confirmation link has already been used';
  end if;

  if v_gift.status <> 'awaiting_confirm' then
    raise exception 'gift % is not awaiting confirmation', v_gift.id
      using errcode = '23514';
  end if;

  -- Out of the service area means refund, not delivery (spec §5 rule 5).
  select a.name into v_area_name
  from public.service_areas a where a.id = v_gift.service_area_id;

  if lower(p_city) <> lower(v_area_name) then
    perform private.gift_transition(v_gift.id, 'declined');
    perform private.release_slot(v_gift.slot_id);
    perform private.refund_gift(v_gift.id);
    raise exception 'we do not deliver to % yet', p_city using errcode = '23514';
  end if;

  v_address_id := private.set_address_for_person(
    v_gift.recipient_person_id, p_label, p_line1, p_line2, p_city, p_pincode
  );

  perform set_config('app.gift_transition', 'on', true);
  update public.gifts
  set delivery_address_id = v_address_id,
      delivery_city = p_city,
      confirm_token_used_at = now()
  where id = v_gift.id;
  perform set_config('app.gift_transition', 'off', true);

  return private.gift_transition(v_gift.id, 'confirmed');
end;
$$;

create or replace function private.refund_gift(p_gift_id bigint)
returns public.gifts
language plpgsql
security definer
set search_path = ''
as $$
begin
  return private.gift_transition(p_gift_id, 'refunded');
end;
$$;

-- Run by pg_cron in M4. Releases abandoned checkout holds, and expires gifts
-- that were paid for but never confirmed before the cutoff.
create or replace function private.expire_stale_gifts()
returns int
language plpgsql
security definer
set search_path = ''
as $$
declare
  v_count int := 0;
  r record;
begin
  -- Abandoned drafts: release the slot, expire the gift. No money was taken.
  for r in
    select id, slot_id from public.gifts
    where status = 'draft' and slot_hold_expires_at < now()
  loop
    perform private.release_slot(r.slot_id);
    perform private.gift_transition(r.id, 'expired');
    v_count := v_count + 1;
  end loop;

  -- Paid but unconfirmed past the cutoff: expire, release, refund.
  for r in
    select id, slot_id from public.gifts
    where status = 'awaiting_confirm'
      and occasion_date <= current_date
  loop
    perform private.gift_transition(r.id, 'expired');
    perform private.release_slot(r.slot_id);
    perform private.gift_transition(r.id, 'refunded');
    v_count := v_count + 1;
  end loop;

  return v_count;
end;
$$;

revoke execute on function private.confirm_gift(uuid, text, text, text, text, text)
```

```sql
create table public.wishes (
  id bigint generated always as identity primary key,
  author_profile_id uuid not null references public.profiles (id) on delete cascade,
  subject_person_id bigint not null references public.people (id) on delete cascade,
  body text not null,
  -- 'message' is a wish someone typed; 'cake' is the automatic post made when
  -- a gift is delivered (spec §5 rule 6).
  kind text not null default 'message',
  occasion_year int not null,
  created_at timestamptz not null default now(),
  constraint wishes_body_length check (length(btrim(body)) between 1 and 500),
  constraint wishes_year_sane check (occasion_year between 2020 and 2100),
  constraint wishes_kind_valid check (kind in ('message', 'cake'))
);

-- One typed message per person per year, but any number of delivered cakes.
create unique index wishes_one_message_per_year
  on public.wishes (author_profile_id, subject_person_id, occasion_year)
  where kind = 'message';

create index wishes_subject_year_idx on public.wishes (subject_person_id, occasion_year);
create index wishes_author_idx on public.wishes (author_profile_id);

alter table public.wishes enable row level security;

-- Readable by anyone who can see the subject, which is the same rule that
-- governs the person record itself.
create policy wishes_select_visible
  on public.wishes
  for select
  to authenticated
  using ((select private.can_see_person(wishes.subject_person_id)));

-- Writable only by the author, and only for someone they actually celebrate.
create policy wishes_insert_own
  on public.wishes
  for insert
  to authenticated
  with check (
    author_profile_id = (select auth.uid())
    and exists (
      select 1 from public.celebrations c
      where c.person_id = wishes.subject_person_id
        and c.celebrator_profile_id = (select auth.uid())
    )
  );

create policy wishes_delete_own
  on public.wishes
  for delete
  to authenticated
  -- A cake post is a record of a delivery, not the sender's to retract.
  using (author_profile_id = (select auth.uid()) and kind = 'message');

-- Delivery closes the loop: the wall shows who sent a cake, which is what
-- makes the next person send one (spec §5 rule 6).
create or replace function private.post_cake_wish()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  if new.status = 'delivered' and old.status is distinct from 'delivered' then
    insert into public.wishes (
      author_profile_id, subject_person_id, body, kind, occasion_year
    ) values (
      new.sender_profile_id,
      new.recipient_person_id,
      'sent a cake',
      'cake',
      extract(year from new.occasion_date)::int
    );
  end if;
  return new;
end;
$$;

create trigger gifts_post_cake_wish
  after update on public.gifts
  for each row execute function private.post_cake_wish();
```

```markdown
# Database notes

## Running the suite

    supabase start
    supabase db reset      # applies migrations, then seed.sql
    supabase test db       # runs supabase/tests/database/*.test.sql

`seed.sql` is local-only. It creates the `tests` schema helpers
(`tests.as_user`, `tests.create_user`, `tests.create_person`,
`tests.race_last_slot`) and committed catalog fixtures. It is never applied by
`supabase db push`.

## Security model

- Every `public` table has RLS enabled. A table with no policy denies
  everything to `anon` and `authenticated`; that is intentional for
  `gifts`, `people` and `payment_events`, which are written only by
  server-side functions.
- Privileged logic lives in the `private` schema as `security definer`
  functions with `search_path = ''` and `execute` revoked from client roles.
- `gifts.status` changes only through `private.gift_transition`. The
  `gifts_guard_status` trigger enforces this even against the service role,
  which bypasses RLS.
- A sender can never read `addresses`. The proof is
  `supabase/tests/database/04_addresses.test.sql`, which asserts zero rows
  rather than an error.
- Ops address reads go through `public.ops_get_delivery_address`, gated on gift
  status and logged to `address_access_log`.

## Things that must not change casually

- `private.config.phone_pepper`: rotating it invalidates every stored
  `people.phone_e164_hash`, orphaning the whole contact graph.
- `private.gift_transitions`: the legal state graph. Add rows; do not delete
  them without checking `gift_events` history.
```
